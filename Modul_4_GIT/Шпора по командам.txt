Шпаргалка (Cheat Sheet) для быстрого доступа
Это 90% команд, которые нужны в ежедневной работе.


🚀 Сценарий 1: Я начинаю новый проект с нуля

# 1. Создай папку и зайди в неё
mkdir my_project && cd my_project

# 2. Инициализируй Git
git init

# 3. Создай файлы (например, README.md)

# 4. Добавь все файлы в отслеживание
git add .

# 5. Сделай первый коммит
git commit -m "Initial commit"

# 6. Создай пустой репозиторий на GitHub (без README!)
# 7. Свяжи папку с GitHub (скопируй ссылку с сайта)
git remote add origin https://github.com/username/my_project.git

# 8. Отправь код на GitHub
git push -u origin master

🔄 Сценарий 2: Я изменил файлы (ежедневная работа)
# 1. Посмотри, что изменилось
git status

# 2. Добавь нужные файлы (или все сразу)
git add .
# или точечно: git add file1.txt

# 3. Сохрани изменения (коммит)
git commit -m "Понятное описание изменений"

# 4. Отправь на GitHub
git push


📥 Сценарий 3: Я хочу забрать чужие изменения (git pull)

# 1. Забери изменения с сервера
git pull

# Если конфликтов нет — всё готово.
# Если конфликт (CONFLICT):
# 2. Открой файл, удали <<<, ===, >>> и оставь нужный текст
# 3. Добавь файл в отслеживание
git add file_with_conflict.txt
# 4. Заверши слияние
git commit -m "Разрешил конфликт"
# 5. Отправь результат на GitHub
git push


🆘 Полезные команды «на всякий случай»
git log — показывает историю коммитов (кто, когда, что).

git branch — показывает ветки (в какой ты сейчас).

git checkout -b new-branch — создает новую ветку и переключается на неё.

git restore <файл> — отменяет изменения в файле (возвращает к последнему коммиту).

git reset — отменяет последнюю попытку git add, ничего не удаляя с диска (очищает кэш Git)

git rm -r --cached "Docker/pg+ch/postgres_data" - убирает папку из «зоны подготовки»,
но не удалит её с компьютера. В кавычках путь к папке, в команду пишем без кавычек)


📜 Полный список команд за первый командный проект (строго по порядку)
1. Настройка (делается один раз на компьютере)

git config --global user.name "Твое Имя" — говорит Git'у, как тебя зовут (для подписи коммитов).

git config --global user.email "твоя@почта.com" — говорит Git'у, на какую почту привязывать коммиты.

2. Инициализация проекта

git init — превращает обычную папку в Git-репозиторий (создает скрытую папку .git).

3. Связка с GitHub

git remote add origin https://github.com/... — связывает твою локальную папку с удаленным репозиторием на GitHub (дает ему имя origin).

git remote -v — проверяет, правильно ли установлена связь (показывает ссылки).

4. Работа с файлами (цикл)

git status — показывает, какие файлы изменились, какие новые, а какие готовы к коммиту (красные — не отслеживаются, зеленые — готовы).

git add <файл> (или git add .) — добавляет файл(ы) в «зону подготовки» (staging area), чтобы Git начал за ними следить.

git commit -m "Сообщение" — делает «снимок» (сохраняет) всех добавленных файлов с твоим комментарием.

git push -u origin master — отправляет твои коммиты на GitHub (первый раз с флагом -u, чтобы связать ветки).

git push — отправляет коммиты на GitHub (когда связь уже установлена).

5. Работа с удаленным репозиторием (для конфликтов)

git pull — забирает изменения с GitHub и пытается объединить их с твоими локальными.

git branch — показывает, в какой ветке ты находишься (звездочка * указывает на текущую).

6. Разрешение конфликтов (ручное)

(Редактирование файла вручную: удаление <<<, ===, >>>)

git add <файл> — говорит Git'у, что ты исправил конфликт и файл готов к слиянию.

git commit -m "Разрешил конфликт" — фиксирует результат слияния.
